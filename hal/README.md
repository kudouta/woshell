# hal — 機種の層（インターフェースのヘッダーと SE/30 の実装）

機種に依存する部分を、この中にまとめています。上の層（`vtermlib/` の端末、`src/` のシェル）は、`include/` のインターフェースのヘッダーだけを使い、SE/30 のレジスタやアドレスには触りません。

| 作るもの | 内容 |
|---|---|
| `build/libse30.a` | SE/30 の実装（`se30/*.c`、`*.S`） |
| `build/crt0.o` | プログラムのエントリーポイント。リンクのときに先頭に置く（ライブラリーには入れない） |
| `build/boot.bin` | フロッピーの起動ブロック。ROM のドライバーでプログラムを `LOAD_ADDR`（0x80000）に読み込む |

Linux では `make`、Windows では `wsl make` のように WSL から、このフォルダーで実行します。

```
make                # 上の 3 つを作る (ふつうは woshell や vtermlib の make から呼ばれる)
```

## インターフェース（`include/`）

機種に依存しない形の関数の一覧です。別の機種に移すときは、このインターフェースを同じ形で作れば、上の層はそのまま使えます。

| ヘッダー | 内容 |
|---|---|
| `platform.h` | 初期化、起動し直し、RAM の大きさ、割り込みの記録、割り込みボタンの記録、ROM の起動のアイコン、物理 RAM を探す（調査用） |
| `video.h` | 画面（1 ドット 1 ビット、32 ビットの語の並び）への書き込み、ずらし、垂直同期を待つ |
| `keyboard.h` | キーボード（文字は ASCII、矢印などは `KEYBOARD_` の値、テンキーは `KEYBOARD_KP` 付き） |
| `timer.h` | 増えていく 32 ビットの時計（1 秒に `TIMER_HZ`） |
| `beep.h` | 短い音 |
| `trap.h` | 例外（バスエラーなど）や割り込みボタンのあとで、決めておいた場所へ戻るしくみ（setjmp / longjmp と同じ考え方） |
| `serial.h` | シリアルポート |
| `rtc.h` | 電池で動く時計と PRAM |
| `cpu.h` | CPU の状態を調べる（調査用）: MMU とキャッシュのレジスタ、変換の表のあらまし、1 つのアドレスの変換 |

`memcpy` や `printf` などの C のライブラリーの関数は、機種に依存しないので `../libc` にあります。

機種の定数（画面の大きさ `VIDEO_W` / `VIDEO_H`、時計の速さ `TIMER_HZ`、名前 `MACHINE_NAME`）は `se30/machine.h` にあります。

## 使う側がすること

- インクルードの場所に `hal/include` と `hal/se30` を入れます。
- `hal/build/crt0.o` を先頭に置き、`hal/se30/stage2.ld` でリンクします。`-L hal/build` を付け、ライブラリーは `-lse30 libc/build/libc.a -lgcc` の順に並べます（端末も使うなら `-lvterm -lse30 libc/build/libc.a -lgcc`）。hal の中でも `memcpy` を使うので、`libc` が要ります。
- リンクのときに `-Wl,--defsym=LOAD_ADDR=0x80000` を渡します（`stage2.ld` が使います）。
- `trap_fatal`（`trap.h`。戻り先を決めていないときに例外が起きたら呼ばれます）を用意します。
- 呼ぶ順: `platform_init()` → `keyboard_init()` → `beep_init()` →（シリアルを使うなら）`serial_init()`
- コンパイルの設定（`-m68030 -m68881 -O2 -ffreestanding` など）は `Makefile` と合わせます。
- プログラムの大きさには上限があります（下の「読み込める大きさ」）。

シリアルを使わないプログラムには `serial.c` が取り込まれません。そのときシリアルの割り込みには、`irq.c` の中にある何もしない弱い定義の `serial_irq` が使われます。

## SE/30 の実装（`se30/`）

| ファイル | 内容 |
|---|---|
| `boot.S` | 起動ブロック。ROM の .Sony ドライバーでプログラムを読み込み、フロッピーを取り出してから飛ぶ |
| `crt0.S`、`stage2.ld` | `crt0.S` はプログラムのエントリーポイント（割り込みを止め、自分の領域のスタックに切り替え、.bss を消して `main` を呼ぶ）。`stage2.ld` はリンカースクリプト |
| `platform.c` | 初期化、起動し直し、RAM の大きさ |
| `via.c`、`via.h` | VIA の初期化と時計（VIA1 タイマー 2 を足し込んで 32 ビットにする） |
| `irq.c`、`irq.h`、`vectors.S` | 割り込みのエントリーと処理、割り込みの記録 |
| `trap.c`、`trapent.S` | 例外のエントリー、レジスタの保存と戻り、割り込みボタンで続けて入る NMI を 1 回の押下にまとめる処理 |
| `video.c` | 内蔵ディスプレイ（512 x 342、1bpp） |
| `adb.c`、`keyboard.c` | ADB キーボードの読み取りと、キーコードから文字への変換（US 配列、キーの繰り返し） |
| `asc.c`、`beep.c` | ASC（Apple Sound Chip）を FIFO モードで使い、垂直同期の割り込みで補充する。ベルの音 |
| `serial.c` | SCC（Z85C30）のシリアル。受信も送信も割り込みとバッファーで行う |
| `rtc.c` | 電池で動く時計（秒のカウンター）と PRAM（256 バイト） |
| `romicon.c` | ROM の中の起動のアイコンを読む |
| `ramscan.c` | 物理 RAM がどこにあるかを 1MB ごとに調べる（CPU の素通しの範囲（TT1。MMU の変換を通さずに物理アドレスを見る）を使い、8MB の窓の外も読み書きする。書いた値はすぐ戻す） |
| `mac.h`、`machine.h` | ローメモリ変数と機種の定数 |

## CPU ごとの部分（`m68030/`）

`Makefile` の `CPU` で選びます。68030 を使う機種なら、機種が違ってもそのまま使えます。

| ファイル | 内容 |
|---|---|
| `m68030/mmu.c` | MMU（PMMU）とキャッシュのレジスタを `pmove` / `movec` で読み、変換の表をたどって表示する（`cpu.h`。読むだけで書き換えない）。物理アドレスを直接見る窓（TT1 を一時的に使う `cpu_phys_window`） |

## 道具（`tools/se30/`）

`mkfloppy.py`（起動ブロックとプログラムからフロッピーのイメージを作る）、`writefloppy.py`（イメージを本物のフロッピーに書く。Windows、管理者のコマンドプロンプト）、`play.lua`（MAME の調査用。決めたフレームでキーを打ち、画面を保存する）があります。

## 割り込み

68030 の自動ベクター（24〜31）と例外のベクター（2〜63）を、すべて自分のエントリーにしています。

| レベル | つながっている回路 | 扱い |
|---|---|---|
| スプリアス | （受け付け中に要求が消えたとき） | 数えるだけ |
| 1 | VIA1: ADB のシフトレジスタ、1 秒、60.15Hz、タイマー | ADB だけ使う。ほかの要因は消して数える |
| 2 | VIA2: スロット（内蔵ビデオの垂直同期、PDS のカード）、SCSI、ASC、タイマー | 垂直同期だけ使う（ベルの音の補充も）。実機で 59.83Hz、MAME では 2 フレームに 1 回 |
| 3 | つながっていない | 数えるだけ |
| 4 | SCC（シリアル） | `serial_irq` に渡す。処理されなければ要因を残して SCC の割り込みを止める |
| 5、6 | つながっていない | 数えるだけ |
| 7 | 割り込みボタン（NMI） | 続けて入る NMI を 1 回の押下にまとめ、押下ごとに 1 回だけ例外と同じエントリーに入れる |

- **割り込みボタン**: SE/30 の実機では、ボタンを押している間ずっと NMI が入り続けます（エントリーがすぐ戻る形で約 13µs に 1 回。0.2 秒押すと 1 万回以上）。エントリー `trap_nmi_entry` で、前の NMI から 50ms 未満なら同じ押下として数えるだけですぐ戻ります。時間は VIA1 タイマー 2 の上位バイトだけで測ります（以前は下位バイトも読んでいましたが、桁が下がる瞬間に 256 カウントずれ、1 回の押下を何十回にも数えてしまいました）。
- **垂直同期の割り込み**: ROM が動いていたときに出た割り込みが残っているので、許可する前に一度下げます（下げないと入りません。実機で確かめました）。

## シリアル（`serial.c`）

- SE/30 には SCC の 2 つのチャンネルにつながったポートが 2 つあります（Apple の資料では、モデムポート = チャンネル A、プリンターポート = チャンネル B）。使うのは一度に 1 つです。
- 8 ビット、パリティなし、ストップビット 1 です。受信は 1 文字ごとの割り込みでバッファー（1KB）にため、送信はバッファー（4KB）に入れて割り込みで送ります（いっぱいのときだけ待ちます）。
- RTxC 端子に 3.6864MHz が入っています。300〜57600bps はボーレート発生器（時定数 = 115200 ÷ 速さ − 2）、115200 / 230400bps は RTxC を直接 32 倍 / 16 倍のクロックとして使います。MAME は後者を再現していないので、実機でしか試せません。
- Mac のシリアルポートは RS-422 の mini-DIN8 です。RS-232 の変換器につなぐときは、3 番（TxD−）→ PC の RxD、5 番（RxD−）← PC の TxD、4 番（GND）と 8 番（RxD+）→ PC の GND とつなぎます。
- MAME の SE/30 では、チャンネル A の名前が `printer`、B が `modem` になっています（Apple の資料と逆）。

## 時計と PRAM（`rtc.c`）

- VIA1 ポート B の 3 本（ビット 0 データ、ビット 1 クロック、ビット 2 選択）で、上位ビットから 1 ビットずつやり取りします。1 回のやり取り（約 100µs）の間は割り込みを止めます。
- 時刻は 1904 年 1 月 1 日 0 時からの秒数です（時差は持ちません）。2040 年 2 月で一周します。秒は 1 バイトずつ読むので、2 回続けて同じ値になるまで読みます。
- 書くときは書き込み禁止を外し、書いてから戻します。
- 本体の電池が切れていると、電源を入れるたびに時計が 0 から始まり、ROM が PRAM を決まった値で初期化し直します。

## ROM の起動のアイコン（`romicon.c`）

SE/30 の ROM（先頭 4 バイトのチェックサムが `$97221136` のもの）では、先頭から `$1948` の位置に 32 x 32 の絵（128 バイト）があり、続く `$19C8` にマスクがあります。MAME の起動の画面に出ているアイコンと ROM の中の並びを照らし合わせて見つけました（絵とマスクで描くと、ROM が描いた画面と 1 ドットも違いません）。ROM の位置はローメモリの `ROMBase`（`$2AE`）から取ります。チェックサムが合わない ROM では読みません。絵そのものはこのリポジトリーには入っていません。

## MMU とキャッシュ（ROM が設定した状態）

woshell の `mmu` コマンドで読んだ、起動したときの状態です（MAME、2026-11-19）。ROM がすでに MMU を有効にしていて、プログラムはその変換の上で動いています。

| レジスタ | 値 | 意味 |
|---|---|---|
| TC | `$80F84500` | 有効。ページ 32KB、**IS 8**（論理アドレスの上位 8 ビットを無視する = 24 ビットのアドレス）、TIA 4・TIB 5 |
| CRP | `$7FFF0002 $40800050` | 短い形の表。**表は ROM の中**（`$40800050`）にある |
| TT0 / TT1 | `0` | 素通しは使っていない |
| CACR | `$00002901` | データのキャッシュと命令のキャッシュが**どちらも有効** |

変換（論理アドレスの下位 24 ビット → 物理アドレス。1MB ずつ、表の最初の段で打ち切っています）:

| 論理アドレス（24 ビット） | 物理アドレス | 中身 |
|---|---|---|
| `$000000-$7FFFFF` | `$00000000`（同じ） | RAM（8MB の窓） |
| `$800000-$8FFFFF` | `$40800000` | ROM |
| `$900000-$EFFFFF` | `$F9000000-$FE000000`（キャッシュしない） | NuBus のスロット 9〜E の空間。内蔵ビデオはスロット E（`ScrnBase` = `$FE008040`） |
| `$F00000-$FFFFFF` | `$50F00000`（キャッシュしない） | I/O（VIA `$50F00000`、SCC `$50F04000` など） |

- 上位 8 ビットを無視するので、`$40800000`（ROM）や `$50F00000`（VIA）のような 32 ビットの形のアドレスも、そのまま正しい場所に届きます。今のプログラムが 32 ビットの形のアドレスを使えているのはこのためです。
- RAM は 8MB の窓までしか見えません（8MB を超える RAM を使うには、自分の表を作って 32 ビットのアドレスにする必要があります）。
- I/O とビデオにはキャッシュしない印が付いているので、データのキャッシュが有効でも、レジスタや VRAM の読み書きは直接届きます。
- 表は ROM の中にあって書き換えられないので、変換を変えるときは RAM に新しい表を作り、CRP と TC を差し替えます。そのときは、今使っているアドレス（RAM、ROM、VIA、SCC、ASC、VRAM、ローメモリが指す先）がすべて同じように見えるようにします。
- 24 ビット / 32 ビットのアドレスモードと MMU の ON / OFF は別のものです。モードは「アドレスの何ビットを使うか」という Mac OS の決まりで、SE/30 の ROM はそれを 68030 の MMU で作っています（IS 8 で上位 8 ビットを無視します）。そのため SE/30 では、24 ビットのモードのあいだ MMU は必ず ON になります。
- SE/30（と IIx・IIcx）の ROM は、32 ビットのアドレスに対応していないことで知られています。32 ビットのモードへは、System が読み込む拡張（MODE32 など）が後から切り替えます。woshell は System より前に起動ブロックから動くので、実機でも 24 ビットのモードのままと見ています（実機ではまだ確かめていません）。

## RAM の量（MemTop と BufPtr）

MAME で RAM の量を変えて読んだ値です（2026-11-19。`ramscan` と、ローメモリを直接読んで確かめました）。

| | 8MB | 32MB |
|---|---|---|
| `MemTop`（$108） | `$00800000` | **`$02000000`** |
| `BufPtr`（$10C） | `$007FFD00` | **`$007FFD00`** |
| 起動のときのスタック | `$003FFBFC` | `$003FFBFC` |
| MMU | 24 ビット（8MB の窓） | 24 ビット（8MB の窓）のまま |

- **`MemTop` は ROM が見つけた物理 RAM の全量**で、24 ビットのモードでも 8MB で頭打ちになりません。8MB の窓に収める調整は `BufPtr`（使える範囲の終わり）と起動のときのスタックの位置で行っています。
- 窓の外の物理 RAM（32MB なら物理 8〜32MB）は、`ramscan 0x800000, 0x4000000` で実際に読み書きできることを確かめました。
- MAME の SE/30 は RAM を物理アドレス 0 から続けて置き、それより上には同じ RAM が繰り返し見えます（写り込み）。MAME で選べる RAM の量は 2MB、8MB、32MB、64MB、96MB、128MB です（`-ramsize` に `2M` などと渡します）。
- 実機（20MB 積んでいる）で以前読んだ `MemTop` は `$00800000`（8MB）でした。ROM は MAME と同じなので、**実機の ROM は 8MB しか見つけていない**ことになります。実機で `ramscan` を実行すれば、残りの RAM が物理アドレスのどこにあるか（あるいは見えていないか）がわかります。

## 読み込める大きさ

起動ブロックは ROM のドライバーでプログラムを 0x80000 に読み込みます。読み込みの途中は ROM のスタックを使っているので、読み込めるのはそのスタックを上書きしない大きさまでです。ROM は起動のときのスタックを、RAM の真ん中のすぐ下（MemTop ÷ 2 − 0x404）に置きます。スタックが伸びてよい下限の ApplLimit は、そこから 0x6040 バイト下にあります。プログラムは 0x80000 から ApplLimit までに収めます。その上限は、RAM 2MB で約 487KB、8MB で約 3.5MB です（8MB ならフロッピーの容量のほうが先に上限になります）。
